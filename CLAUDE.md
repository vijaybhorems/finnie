# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Finnie is a multi-agent AI finance-education assistant: LangGraph orchestrates a cache → classify → one-of-six-agents pipeline, backed by a FAISS RAG knowledge base and live market/macro/news data clients, served through a Streamlit UI behind Google OAuth.

CI (`.github/workflows/ci.yml`, GitHub Actions) runs `pytest` on every PR and push to main, with a pgvector Postgres 16 service and `FINNIE_TEST_DATABASE_URL` set, so the Postgres variants of the persistence, isolation, pgvector and memory tests run there too. It installs CPU-only torch first, as the Dockerfile does. No secrets: live evals stay on demand.

There is no configured linter/formatter (no ruff/black/mypy config) — `pyrightconfig.json` sets `basic` type-checking mode only.

Tests auto-mock required env vars and clear LRU-cached singletons (`get_settings`, `get_llm`, `build_graph`, circuit breakers, persistence backends) between tests via autouse fixtures in `tests/conftest.py` — no manual cache-clearing needed when writing new tests. `conftest.py` sets `DATABASE_URL=""` so the suite always uses the in-memory backend, even when a developer's `.env` points at a real database, and swaps the store's embedding function for a deterministic `hash_embed` (every turn searches memories; without it each test would load the real model). Mark a test `@pytest.mark.real_embeddings` to opt out.

## Architecture

**Request flow:** `src/workflow/graph.py` builds a LangGraph `StateGraph` over `FinnieState` (`src/core/state.py`): `START → faq_cache → (hydrate → classify → one of 6 agent nodes → faq_cache_write) | END`. `run_workflow()` is the single entry point; `stream_workflow()` is the streaming variant used by `src/web_app/views/chat.py`. Both take `user_id` (signed-in user) and `thread_id` (a persistent conversation); see Persistence below.

The graph shape is controlled by two independently reversible flags under `fast_path` in `config.yaml` — with both off it rebuilds the original `START → guardrail → router → agent → END` pipeline, which is still tested:

- **FAQ cache** (`src/workflow/faq_cache.py` + `src/utils/semantic_cache.py`, flag `fast_path.faq_cache.enabled`) runs first. Exact match on the normalised query, then cosine over cached query embeddings at `similarity_threshold` (0.92). A hit ends the turn with zero LLM calls. `faq_cache_write` runs after each agent and only stores answers that are safe to reuse: `finance_qa`/`tax_education` only, `needs_macro is False`, not a follow-up, and no live market data in `financial_data`. Every entry is stamped with `get_kb_version()` (hash of the knowledge base) and the tax year, and ignored once either moves. Every cache operation fails open — an error is a miss, never a failed turn. Storage (`fast_path.faq_cache.backend`): `PostgresFAQCache` — a `faq_cache` table shared by every instance, validity enforced in SQL, exact matches answered without embedding the question — when `DATABASE_URL` is set; otherwise `SemanticFAQCache` on Redis with a per-process vector index.
- **Classify** (`src/workflow/classify.py`, flag `fast_path.merged_classifier`) replaces the guardrail and router with one `with_structured_output(Verdict)` call returning `{on_topic, agent, needs_macro, reason, tickers}`. `tickers` resolves company names to symbols ("Apple" → AAPL); `classify_node` validates them into `FinnieState.query_tickers`, which `MarketAnalysisAgent` fetches ahead of the uppercase symbols it extracts itself (that extraction alone misses names, which is how voice users ask). Same safety contract as before: blocklist fast path (no LLM call), fails closed to `GuardrailConfig.refusal_message` on any error, malformed verdict, or off-topic result. `needs_macro` gates the FRED fetch in `FinanceQAAgent` — `None` means the legacy path ran and agents fetch unconditionally. Follow-ups ("What's the exact dollar amount?") mean nothing alone, so the classifier also gets `conversation_context()`: the previous user question and the start of Finnie's answer (`previous_turn(state.messages)`), in the user message, never the system prompt; the verdict's `follow_up` flag goes to `FinnieState.follow_up`, and `faq_cache_write` never stores a follow-up's answer. A bare "Stop." / "wait" / "never mind" (`is_acknowledgement()`) skips the model and ends the turn with `ACKNOWLEDGEMENT` as `AgentType.ACKNOWLEDGE` (not learned from, like refusals). `classify_query()` keeps a 120 s per-process verdict cache keyed on the normalized query text and that context, so a caller that classifies early (the voice worker, while the user speaks) saves the graph a second call, and concurrent calls for the same key share one model call — the worker builds the same context from the previous turn's question and `final_response`, so keep the two in step; `tests/conftest.py` clears it between tests. `llm.classifier_reason` (default on; the voice worker turns it off) asks for the `reason` field: it is written after the decision, so it never changes it, but it is about 0.35 s of a Haiku verdict; without it the model fills `Routing` (the decision alone) and `reason` is `""`.
- **Legacy nodes** (`src/workflow/guardrail.py`, `router.py`) are still present and tested; `classify.py` imports the blocklist helper from `guardrail.py` rather than duplicating it.
- **Streaming** (flag `fast_path.streaming`) sets `streaming=True` on the shared `ChatAnthropic`, which is what makes LangGraph's `stream_mode="messages"` emit per-token events from `.invoke()` inside agent nodes. `stream_workflow()` filters those to `AGENT_NODES` so the classifier's own tokens never reach the UI, forwards message chunks only (the finished `AIMessage` an agent returns is emitted too and would repeat the answer), then flushes the disclaimer the agent appends after the model call. `channel="voice"` (on `run_workflow`/`stream_workflow`, carried in `FinnieState.channel`) adds a short-answer instruction to the per-request prompt block and skips the FAQ cache in both directions. `get_llm(streaming=False)` is used for the structured classifier call.
- **Parallel fetches**: agents that hit more than one provider per turn (`finance_qa`, `portfolio`, `market_analysis`, `news_synthesizer`) issue them concurrently through `gather()` in `src/utils/parallel.py`; a failing task yields `None` and a warning rather than failing the turn.
- **Embeddings**: `src/core/embeddings.py` owns the one `SentenceTransformer` instance, shared by the RAG retriever/indexer and the FAQ cache — don't construct a second one.
- **Agents** (`src/agents/`) all extend `BaseAgent` (`src/agents/base_agent.py`), which owns: system-prompt assembly + disclaimer injection, and `_invoke_llm(state, context)` — a retry wrapper (3 attempts, exponential backoff) around transient `httpx` connection errors, emitting structured `llm_call_*` logs that include the prompt-cache usage fields. Agents are lazily instantiated singletons per process (`_AGENTS` dict in `graph.py`), each holding its own `get_llm()` client.
- **Prompts and prompt caching** (`src/agents/prompts/`, flag `llm.prompt_caching`): each agent's system prompt is three content blocks, most stable first, because Anthropic caching is a prefix match — (1) `shared_system_prompt()`: `finnie_core.md` + a knowledge-base digest (`src/rag/digest.py`), byte-identical across all six agents so one cache entry serves them all; (2) the agent's role block: name, description, `<agent>.md`, and `_static_reference()` data such as the tax tables; (3) "Context for this request": the `context` string passed to `_invoke_llm` — profile, retrieved passages, live data. Blocks 1–2 carry `cache_control`; block 3 does not.
  - **Never put per-request data in blocks 1–2** (a date, user id, query, or anything fetched per call). It still works — every request just becomes a cache write at 1.25× instead of a read at 0.1×, and nothing errors. Pass it through `context` instead.
  - Claude Sonnet 5 won't cache a prefix under 1,024 tokens; block 1 is sized to clear that alone. Shortening `finnie_core.md` or the knowledge base can drop it below — `prompt_cache_inactive` is logged once per agent when a call reads and writes nothing.
  - Prompts are sent as message objects, not a `ChatPromptTemplate`, so braces in RAG text or JSON data need no escaping.
  - After changing prompt assembly, run `FINNIE_EVAL_LIVE=1 pytest tests/evals/test_prompt_cache_evals.py -v -s` — the usage fields are the only proof the cache still hits.
- **Persistence** (`src/persistence/`, `persistence` in `config.yaml`): per-user profile, holdings, saved Goals plan, and chat history. Postgres when `DATABASE_URL` is set (LangGraph `PostgresSaver` for threads + `PostgresStore` for user data, one pool); in-process memory otherwise — nothing survives a restart there, and a `persistence_in_memory` warning says so. `build_graph(persistent=True)` adds the checkpointer (chat page); `build_graph()` stays stateless (one-shot tabs, evals). Both get the store.
  - **Identity**: `user_id` is `g-<Google sub>` from `st.user` (`src/web_app/session.py`, recomputed every call — never cached, never taken from page input). **All** user data goes through `UserData(user_id)`, which is bound to that one namespace and has no way to address another; thread ids are minted as `<user_id>:<uuid>` and `run_workflow`/`load_conversation`/`delete_conversation` refuse a thread whose prefix isn't the caller's. Isolation is application-level by design — LangGraph owns the tables and queries, so Postgres RLS has no per-request hook. `tests/test_persistence.py` is the cross-user leakage suite; keep it passing on Postgres.
  - **hydrate node** (`src/workflow/hydrate.py`) loads the user's saved data into `state.user_profile` after an FAQ-cache miss. Profile fields the user never saved stay `None` (`UserData.get_chosen_profile()`; `get_profile()` fills defaults for the sidebar only), and `BaseAgent._get_user_context_str` lists them as not set: a default rendered as `investment_horizon=long` made the model tell an empty user "since you're young". `finnie_core.md` ("What you know about the user") tells agents to state facts about the user only from the context and otherwise speak conditionally. It reads the store through LangGraph's injected `store` parameter, which is only injected for the annotation spelling `Optional[BaseStore]`/`BaseStore` — `BaseStore | None` silently disables it and every turn loses personal context with no error (`TestHydrate` catches this).
  - **Per-turn reset**: on a checkpointed thread every `FinnieState` field except `messages` carries into the next turn. `turn_state_reset()` (built from the model's defaults) is applied to each turn's input — add new fields to `FinnieState` with sensible defaults and they are reset automatically; never compute per-turn values that rely on the previous turn's state.
  - **Checkpoint allow-list**: the checkpointer's serializer revives only LangGraph's built-in safe types plus `CHECKPOINT_TYPES` in `backend.py` (`AgentType`, `UserProfile`, `FinancialData`). A new model or enum reachable from `FinnieState` goes there too (a test fails until it does); otherwise LangGraph logs `Deserializing unregistered type` and a future version will refuse it, so saved threads would stop loading. Chat and the voice worker both get it through `get_checkpointer()`.
  - Agents send at most `workflow.max_history_messages` of history (`trim_history`, window always opens on a user turn); the full thread stays in the checkpoint. Guardrail refusals are appended to `messages` so a refused question is never left unanswered in history.
  - Pages save only on a real change or an explicit button (`save_if_changed`) — the Portfolio tab's example holdings and the Goals timeline's defaults are never saved as a user's own. Holdings are sanitised on write (`clean_holdings`): Postgres `jsonb` rejects the `NaN` that `st.data_editor` returns for blank cells.
- **Memory** (`src/memory/`, `memory` in `config.yaml`): durable facts users state in chat ("saving for a house deposit, target 2028"), recalled in later sessions.
  - **Write path**: after each on-topic chat turn, `chat.py` calls `schedule_remember_turn()` — a background thread, so the answer never waits. `extract_facts()` skips the model entirely unless the message has a first-person word, asks for structured facts (goal/situation/preference/constraint + confidence), and `remember_turn()` keeps only confidence ≥ `min_confidence` and drops anything `is_sensitive()` flags (account/card/SSN-like digit runs, emails, passwords) — a deterministic backstop to the prompt's exclusions. A fact nearly identical (`dedup_similarity`) to an existing one in the same category replaces it.
  - **Storage**: `UserData.remember/forget/forget_all/list_memories/relevant_memories`, one store item per fact in `("users", <id>, "memories")`, semantically indexed on `fact` with exact (`flat`) search. Only memory items are indexed — other `UserData` writes pass `index=False` and never embed. Deletes are real store deletes (the vector row cascades).
  - **Read path**: hydrate adds the `top_k` memories relevant to the question to `user_profile.memories`; `BaseAgent._get_user_context_str` puts them, dated, in the per-request context block (never the cached blocks).
  - **Privacy rules — keep them**: `faq_cache_write` never stores an answer produced with memories, because the FAQ cache is shared by every user. The user's switch (`memory_enabled`) stops both saving and recall. Voice calls save memories too, under stricter rules (see Voice). The sidebar panel (`src/web_app/memory_panel.py`) lists, deletes, and forgets everything.
- **Voice** (`src/voice/`, `voice` in `config.yaml`, off by default): a LiveKit worker (Deepgram → `stream_workflow(channel="voice")` → ElevenLabs) that runs the same graph in-process. Design doc: *Finnie Voice Agent — Design*.
  - **Join checks** (`access.py`, pure, no LiveKit import): `check_join()` runs when a call joins and re-reads the flag and allowlist, so a token minted earlier stops working. Identity must be `g-<sub>`, the room `<identity>:<32 hex>`, and the token metadata's email allowlisted. An empty `voice.allowed_emails` lets nobody in (unlike the app's `ALLOWED_EMAILS`); `["*"]` lets everyone. A refused call hears `VOICE_UNAVAILABLE` (or `DAILY_LIMIT` when the day's minutes are gone), ends, and saves nothing.
  - **Threads**: the room name is the call's thread id, so `_check_thread_owner` covers voice too. `UserData.start_voice_call()` records it under `("users", <id>, "voice_calls")` and never touches `session.active_thread_id`: a call must not replace the Chat page's conversation. `tests/test_persistence.py` covers voice isolation.
  - **Tokens** (`tokens.py`): `mint_call_token(user_id, email)` is the only way the app should start a call; call it server-side with the identity from `session.py`. It refuses (`VoiceRefused`, with a page-safe `message`) unless voice is allowed for the email, LiveKit is configured (`LIVEKIT_URL`/`_API_KEY`/`_API_SECRET`, no defaults in the app), the user has daily minutes left and fewer than `voice.tokens_per_hour` tokens in the last hour. Tokens join one new room, publish microphone audio only, and expire after `voice.token_ttl_minutes` if unused. Minting closes the user's other open rooms (one call per user). `livekit-api` is in `requirements.txt` for this; the rest of LiveKit is not.
  - **Page** (`src/web_app/voice.py`, `voice_panel.py`, `voice_call/`): shown only when `voice_offered()` (the allowlist). Talk sits beside the chat input; the first press shows the privacy notice (`CONSENT_TEXT`, saved by `set_voice_consent()`), later presses mint a token and rerun into the call view. The call view is an `st.components.v2` component that holds the LiveKit connection in the browser and draws the live transcript, answer cards and call bar itself, so call events cause no Streamlit reruns; it reports back only `speak_amounts` (saved for this call) and `ended` (with a reason; `END_MESSAGES` turns failures such as `mic_denied` or `agent_left` into a toast). The worker sends the page `page_events.py` events on topic `finnie.voice`, addressed to the caller only: each turn's full written answer (`answer`), what was said aloud (`spoken`), and notices. Send them through `page_sender()`, bound on the job's event loop: LiveKit keeps the job in a context variable, so a coroutine scheduled from the graph's thread can't find the room and the event is silently lost. The sidebar's Voice calls panel holds "Speak amounts by default" and deletes calls (transcript thread and record). The embedded browser pane blocks the microphone; test calls in a real browser (spike/voice/README.md).
  - **Limits** (`limits.py`, pure): `CallMonitor` decides the call's length (the smaller of `max_call_minutes` and what is left of `daily_minutes_per_user`), the spoken two-minute warning, the idle prompt and hang-up, and the turn cap. The worker feeds it user/agent state events and calls `tick()` once a second. Voice seconds are saved to `UserData.add_voice_seconds()` every 30 s, and the rest when the session closes, so a crash loses at most 30 s.
  - **Ending a call**: every end (hang-up, a limit, the room closed by a new token) goes through the session's `close` handler, which saves usage, marks the call ended, deletes the room and shuts the job down. Don't rely on job shutdown callbacks alone: after a hang-up LiveKit keeps the job alive about 20 s and they may not run.
  - **Background voices**: `voice.noise_cancellation: bvc` runs LiveKit's background voice cancellation (`livekit-plugins-noise-cancellation`, in `requirements-voice.txt`) on the caller's mic before VAD and Deepgram, through `_room_options()`. Without it, a TV or housemate was transcribed and interrupted answers (first test calls, 2026-11). It is authorised by LiveKit Cloud only: on the local dev server it logs `noise cancellation is not authorized for this connection` and passes audio through unchanged, so local sims run as before.
  - **Interruptions**: `voice.interruption_mode: adaptive` uses LiveKit Cloud's model to tell a cut-in from a backchannel ("uh huh"). LiveKit turns it off in `worker start` (production mode) unless it is named, so keep it spelled out. If the gateway is unreachable (401 on the local dev server) or misses LiveKit's fixed 0.7 s answer limit (seen from a home network on a Cloud project, 2026-11), LiveKit logs `adaptive interruption disabled due to unrecoverable error` and uses voice activity alone for the rest of the call, so `backchannel` ("uh huh" answered as a question) fails. Judge it from the worker pool's logs, not a laptop. LiveKit stops the audio; the graph run is left to finish (cancelling would leave the question unanswered), and the full answer is saved. What the user heard (LiveKit's interrupted chat item, preamble removed) goes into the next turn as `FinnieState.interrupted_after`, which `BaseAgent._build_messages` puts in the per-request block. Before answers about specific securities (market, portfolio, news naming a company: `turns.preamble()`), the worker says "This isn't a recommendation to buy or sell." first, decided in code from the verdict, so an interruption can't cut it off.
  - **Failures** (`turns.py`, `health.py`): no first token by `slow_turn_notice_seconds` → "This is taking longer than usual"; by `slow_turn_abandon_seconds` → an apology and the turn stops being read. A graph error is spoken as an apology, never its error text. Speech with no transcript for `stt_stall_seconds`, or a Deepgram outage (counted once, then again each `stt_stall_seconds` it lasts, since LiveKit retries several times a second) → "I'm having trouble hearing you"; the `stt_stalls_to_end`-th in a row says `HEARING_GIVE_UP` and ends the call. `vendor_error_tolerance` keeps LiveKit from closing the session on its own first (its default, 3 reconnects, is about 2 s and leaves the call silent). Speech falls back from ElevenLabs to Deepgram Aura (`tts_fallback_model`, a second vendor) through LiveKit's `FallbackAdapter`. `VendorHealth` keeps Deepgram/ElevenLabs breakers in the shared cache because each call is its own short-lived process: without Redis a breaker only sees one call. A new call refuses at once while Deepgram's breaker is open, and leaves out a voice whose breaker is open.
  - **Memory from calls** (`memory.py`, pure): after each answered turn (not refused or failed, and the graph run finished even if the user interrupted) the worker calls `schedule_remember_turn(..., min_confidence=voice.memory_min_confidence)`, stricter than chat's, and skips turns whose Deepgram `transcript_confidence` (on LiveKit's user `ChatMessage`) is below `voice.memory_min_transcript_confidence`, since a misheard sentence becomes a wrong fact. The call's close handler (and the shutdown backstop, whose `shutdown_process_timeout` is raised to fit) waits up to `voice.memory_wait_seconds` for saves still running; a miss is logged, not retried. `is_sensitive()` also catches digits spoken as words.
  - **Amounts: discreet by default**: voice answers don't say dollar figures unless `UserData.speak_amounts(thread_id)` is on: the call's own switch if set, else the saved default (`set_speak_amounts(enabled, thread_id=None)`). The worker reads it each turn and passes `speak_amounts` to `stream_workflow`; `BaseAgent` adds `_DISCREET_AMOUNTS` or `_SPOKEN_AMOUNTS` to the per-request block. Backstop: `speech.mask_amounts()` (via `spoken_answer(discreet=True)`) replaces any dollar figure with "the amount on your screen". Only speech changes; the saved answer keeps its figures. `_VOICE_INSTRUCTION` also tells the model to use memories silently unless asked.
  - **Speech evals** (design doc, Evaluation): layer 1 `tests/evals/test_speech_shaping.py` (CI) streams each agent's written answer through `spoken_answer` in token-sized pieces: no markdown, no written disclaimer, amounts per the user's choice, and `speech.normalize_for_speech()` ("$1.2M" → "1.2 million dollars", "401(k)" → "four-oh-one-k", AAPL → "Apple" via `TICKER_NAMES`). Layer 2 `test_voice_routing_evals.py` (live) mirrors `ROUTING_CASES` as transcripts and judges voice answers; it fails if `mask_amounts` had to fire, since the model should not write figures in discreet mode. Layer 3 `test_stt_evals.py` (`FINNIE_EVAL_AUDIO=1`) uses `src/voice/stt.py`'s `deepgram_options()` (the worker's own) and scores `clean_transcript()` output, which rewrites what Deepgram spells out ("four zero one k" → "401(k)"); thresholds sit just under the last run. Layer 4 is `scripts/voice_latency.py`. Layer 5 `test_simulated_calls.py` (`FINNIE_EVAL_CALLS=1`, voice venv, local LiveKit) plays the scenarios in `tests/evals/sim_calls.py` (pauses, backchannel, cut-in, noise, accents, an LLM-written follow-up, silence) over audio against a real worker that `sim_caller.Worker` starts itself (in-memory store, short idle times via `FINNIE_VOICE_SETTINGS`, a JSON of `voice.*` overrides that refuses unknown keys); checks read the turn log (matched by `user_id`), the `voice_call_summary` line and the page events. `scripts/voice_turn_sweep.py` replays the `turn_taking` scenarios across a grid of voice settings (endpointing delays, interruption words). `src/voice/runtime.py`'s `configure_process()` sets the worker's models and is called by the voice evals too.
  - **Monitoring** (design doc, Monitoring): the worker calls `setup_logging()` so its lines are JSON with a Cloud Logging `severity` (without it they were console text, unparsed and unredacted). `voice_call_summary` (`src/voice/usage.py`, pure) is the one line per call: the worker's own end reason (`_END_REASONS`, since LiveKit reports its hang-ups as `user_initiated`), turns, interruptions, backup voice, vendor failures, speech usage from LiveKit's `session.usage`, Claude tokens from a `TokenMeter` callback the worker passes to `stream_workflow(callbacks=…)` and `classify_query(…, callbacks)` (LangChain hands it to nested model calls), and `cost_usd` from `voice.cost` list prices. Prices match a model name exactly, or with a `-YYYYMMDD` suffix: never by prefix, since `claude-sonnet-5` prefixes `claude-sonnet-5-5`. Unpriced models are listed, not guessed. Every graph run's config carries `metadata.channel` and a `channel:<name>` tag for Phoenix. `deploy/voice_monitoring.py` (stdlib) writes the log-based metrics and PromQL alert policies the wizard's Voice alerts stage applies; `tests/test_deploy_voice_monitoring.py` checks they read events and fields the worker really logs, so rename a log field there too.
  - **Time to first audio** (a turn's order in `llm_node`): the final transcript is classified the moment it arrives (interims one at a time, newest next), the graph thread starts at once beside the turn's own verdict (its hydrate overlaps the classifier, and its classify step shares the same model call), the preamble (a `prefetch.FILLERS` line for every agent route, then the securities line) is spoken when the verdict lands, and the answer's first sentence is pushed to TTS with a `FlushSentinel` (LiveKit's sentence splitter otherwise holds it until the next sentence begins). `_VOICE_INSTRUCTION` asks for a ~10-word first sentence, since nothing is spoken until it ends. The turn log's `verdict_s`, `finnie_first_token_s` and `finnie_first_sentence_s` time these steps (`scripts/voice_latency.py`).
  - **Worker process**: `configure_process()` applies `voice.classifier_model`, `voice.classifier_reason`, `voice.llm_thinking` and `voice.db_pool_max_size` to the worker's own settings at import, before anything builds an LLM client or pool. The worker's LiveKit packages live only in `requirements-voice.txt` (only `livekit-api`, for tokens, is in `requirements.txt`); keep LiveKit imports out of `access.py`/`speech.py`/`limits.py`/`turns.py`/`health.py`/`memory.py`/`stt.py`/`runtime.py`, which the app and CI import. The worker's logs never include what was said; `VOICE_TURN_LOG` writes it to a local file for measurement only.
- **Deployment** (Cloud Run + Cloud SQL; README "Deploying to Google Cloud Run"): `docker/entrypoint.sh` runs `python -m src.persistence.migrate` before Streamlit when `DATABASE_URL` is set, so a revision with a broken database never takes traffic. `migrate` takes its lock with a polling `pg_try_advisory_lock`, **never a blocking `pg_advisory_lock`**: LangGraph's store setup runs `CREATE INDEX CONCURRENTLY`, which waits for every open transaction, so a waiter blocked inside a lock statement deadlocks it (reproduced with 4 concurrent migrations on a fresh database). `cloudbuild.yaml` deploys an immutable `:$BUILD_ID` image with `gcloud run deploy`, which merges into the live service — unnamed settings (VPC connector, env vars, other secrets) carry over. `env-vars.yaml` is git-ignored (email allowlist); an empty `ALLOWED_EMAILS` lets any Google account in.
  - **Voice worker** (`_VOICE=1`, saved by `setup_gcp.sh`'s Voice stage, which stores the LiveKit/Deepgram/ElevenLabs keys in Secret Manager): `docker build --target voice` installs `requirements-voice.txt` on top of the app's venv with `-c <pip freeze>`, so the worker and app run the same LangGraph over the shared checkpoint tables — keep that constraint. It deploys as the Cloud Run worker pool `finnie-voice` after the app. `deploy/worker_env.py` (stdlib only; runs in Cloud Build) copies the app service's secret references and voice flag/allowlist to the worker on every deploy, so add a new secret the graph needs to its lists, not to `cloudbuild.yaml`. The wizard keeps `FINNIE_VOICE_ENABLED=0` on the app until the worker pool exists (`VOICE_PENDING` in `deploy/.gcp.env`) and turns it on after the first voice deploy, so Talk never shows without a worker; the worker starts fine with the flag off, since `check_join` reads it per call. The wizard's settings file is `deploy/.gcp.env`: set `ENV_FILE` outright below its library, which already defaults it to the app's `.env`. Sizing: `voice.idle_processes` prewarmed processes (`num_idle_processes`, prod only; ~850 MB each) and `voice.job_memory_warn_mb`. A worker pool gets 10 s from SIGTERM to SIGKILL, so a deploy ends calls in progress.
- **State** (`FinnieState`) is the single object threaded through every node: conversation `messages` (LangGraph-managed via `add_messages`), routing fields, guardrail verdict (`is_on_topic`), `UserProfile`, `FinancialData` payload, `rag_context`, and `final_response`.
- **Config** (`src/core/config.py`): `get_settings()` is an `lru_cache`d singleton merging `config.yaml` (nested `LLMConfig`/`RAGConfig`/`CircuitBreakerConfig`/`GuardrailConfig`/`TracingConfig`/`PlanningConfig`/etc.) with env vars from `.env` (API keys, Redis host/port, Phoenix endpoint/key). If `AWS_SECRETS_NAME` is set, secrets are pulled from AWS Secrets Manager into the env *before* Settings loads (production path; local dev just uses `.env`). Env vars generally win over YAML (see Redis/Phoenix override logic at the bottom of `get_settings()`). `llm.thinking` defaults to `adaptive`, which sends no `thinking` parameter, so Claude Sonnet 5 may think silently before its first text token (about 9 s on goals questions). `FINNIE_LLM_THINKING=disabled` turns it off for one process; the voice spike worker sets it. `llm.classifier_model` (env `FINNIE_CLASSIFIER_MODEL`, unset = `llm.model`) gives the merged classifier its own model; the voice worker uses `claude-haiku-5-5`. Compare accuracy with `spike/voice/compare_classifier.py` before changing it for chat.
- **Resilience**: each external data client (`src/data/{yfinance,alpha_vantage,fred,news}_client.py`) is wrapped in its own circuit breaker (`src/utils/circuit_breaker.py`) — opens after `failure_threshold` consecutive failures, stays open `recovery_timeout_seconds`, then allows one half-open probe. Caching (`src/utils/cache.py`, Redis with in-memory fallback) sits in front of these clients: 5 min for market data, 1 hour for macro, 24 hours for fundamentals.
- **RAG** (`src/rag/`, `rag.backend`): two interchangeable retrievers behind `get_retriever()`, same `search()`/`get_context()` interface and result shape. `auto` picks pgvector when `DATABASE_URL` is set, else FAISS — the suite and any deploy without a database use FAISS.
  - **pgvector** (`pgvector.py`): `kb_chunks` table; hybrid search — exact cosine and a Postgres full-text OR-query, each contributing `hybrid_candidates`, fused by reciprocal rank fusion (`score` is the RRF score, `similarity` the cosine). Exact search is deliberate, not an ANN index: at tens-to-thousands of chunks it is sub-millisecond with perfect recall and avoids HNSW's filtered-search recall loss; add HNSW past ~10k rows and measure. `sync_knowledge_base()` runs at startup (`warm_up`) and via `python -m src.rag.sync`: it embeds only new/changed chunks (content hash + model name), deletes chunks whose files are gone, never touches rows whose `origin` isn't `'repo'`, and is serialised by an advisory lock so instances starting together don't race. `ensure_schema()` creates the extension and tables and refuses to run if `embeddings.dimension` no longer matches the column.
  - **FAISS** (`indexer.py` + `retriever.py`): builds from `src/data/knowledge_base/<category>/*.{txt,md}` (6 categories) into `data/faiss_index` — baked into the Docker image, so a deploy without a database still has retrieval. Both backends chunk through the same `load_documents()`/`chunk_documents()`, so chunk ids and text are identical — `tests/evals/test_rag_backend_parity.py` compares them on the real corpus (at last measure: MRR@5 0.950 pgvector vs 0.867 FAISS, equal hit@5).
- **Planning engine** (`src/planning/`): a *pure, deterministic* projection engine separate from the LLM agents. `life_events.py` defines a closed catalog of 6 event kinds (inheritance, home purchase, child birth, college funding, job change, retirement start); `projection_engine.py` folds them year-by-year onto a baseline savings projection. With zero events it must reproduce `_project_savings` in `src/agents/goal_planning_agent.py` exactly — preserve that invariant when touching either. Defaults/caps (`default_inflation`, `max_horizon_years`, `max_events`) live under `planning` in `config.yaml`. Covered by `tests/test_life_events.py` and `tests/test_projection_engine.py`.
- **Web app** (`src/web_app/`): Streamlit, 4 tabs (Chat/Portfolio/Market/Goals under `views/`), switched by `app.py`'s own navigation. **Never name a directory `pages/` next to `app.py`**: Streamlit auto-registers every file in it as a separate page with its own URL and sidebar link, and those pages run *without* `app.py` — so without the sign-in gate. Every page is gated behind Google OAuth (`auth.py`); `st.user.is_logged_in` raises if OAuth isn't configured, so the app cannot render at all without it (no local-dev bypass). `auth_bootstrap.py` auto-generates `.streamlit/secrets.toml` from env vars in production when `GOOGLE_CLIENT_ID` is set. Load order matters for page speed: `app.py` imports nothing LangChain-related before the auth gate, so the sign-in page paints at once; the workflow and embedding model load in a background thread (`warmup.py`, started at boot by `serve.py`, the container's entry point), and signed-in pages `warmup.wait()` for it. In the container (`FINNIE_WARM_BEFORE_SERVE=1`, set by `docker/entrypoint.sh`) `serve.py` holds the port closed until the warm-up finishes, so Cloud Run's TCP startup probe only routes traffic to a warm instance; with request-based CPU an instance is throttled as soon as it is ready, which is why the service also runs `--no-cpu-throttling`. Keep new heavy imports behind the gate, and keep heavy packages out of `requirements.txt` (the image) — dev-only ones such as the full `arize-phoenix` belong in `requirements-dev.txt`. Styling lives in `.streamlit/config.toml` (`[theme]`) plus `theme.py` (CSS, sign-in page, `page_header()`).
- **Tracing** (`src/core/tracing.py`): `setup_tracing()` is a no-op unless `tracing.enabled` — instruments LangChain/LangGraph via OpenInference, exporting router decisions, guardrail checks, and full LLM prompt/response spans to a Phoenix collector. Exporter protocol is inferred from the endpoint scheme: `https://` → OTLP/HTTP (required for Cloud Run), `http://host:port` → gRPC (local dev via `phoenix serve`).

## Conventions

- Agents must not recommend specific securities as buys/sells and must append the standard disclaimer (`BaseAgent._add_disclaimer`) when discussing specific investments — this is asserted by evals in `tests/evals/test_disclaimer_evals.py`.
- New external data providers should follow the existing pattern: a dedicated client in `src/data/`, wrapped in its own circuit breaker, fronted by the Redis/in-memory cache.
- New life-event kinds go in `src/planning/life_events.py`'s closed catalog and must be folded into `projection_engine.py`'s year-by-year loop — keep the zero-events-reproduces-baseline invariant intact.
- `CHANGELOG.md` records every PR merged into `main`. `.github/workflows/changelog.yml` (via `scripts/changelog_add.py`) adds each one under **Unreleased** after merge, from the PR title, or from a `Changelog: <Added|Changed|Fixed>: <text>` line (or `Changelog: skip`) in the PR description. Write that line in PRs whose title doesn't say what changed for users; don't edit the Unreleased section by hand in a PR.
